# 핵심 기능

- 최신화: 2026-09-16 전달된 확정 사항 반영
- 확정된 내용은 서술형으로 작성하고, 아직 정하지 않은 항목은 [재확인 필요] 또는 [추가 검토 필요]로 표시한다.
- 구체적인 수치·운영 기준이 전달되지 않은 항목은 임의로 확정하지 않는다.

## 1. 이벤트 관리

### 이벤트 등록 및 관리

- 이벤트 이름, 설명, 이미지, 참여 기간을 관리한다.
- 여러 응모 이벤트를 개설할 수 있으며, 이벤트별 경품 및 당첨 인원을 설정한다.
- 이벤트는 응모권 미사용 이벤트와 응모권 사용 이벤트로 구분한다.
- 응모권 미사용 이벤트의 필요 응모권 수는 0장이다.
- 참여 조건에 유플러스 멤버십 등급을 적용한다.
- 관리자와 임직원은 참여할 수 없다.

### 응모권 미사용 이벤트

- 응모권 차감 없이 이벤트에 응모한다.
- 원하는 경품을 선택하지 않고 이벤트 자체에 응모한다.
- 다음 경품 구성을 지원한다.
  - 등수별 경품과 당첨 인원을 설정하는 방식
    - 예: 1등 1명, 2등 5명, 3등 20명
  - 단일 경품에 당첨 인원을 설정하는 방식
    - 예: 동일 경품의 당첨자 1명 또는 50명

### 응모권 사용 이벤트

- 지정된 시각에 모집을 시작하고 정해진 시간 동안 응모를 받는다.
- 모집 마감 후 해당 모집 구간의 유효 응모자를 대상으로 추첨한다.
- 예: 15시부터 15시 10분까지 모집 후 추첨한다. 모집 시간을 10분으로 고정하는 정책은 아니다.
- 가중치 적용 여부에 따라 응모 방식을 구분한다.
  - 가중치 적용: 응모권을 여러 장 사용할 수 있다.
  - 가중치 미적용: 응모권 1장만 사용할 수 있으며, 참여자에게 동일한 추첨 가중치를 적용한다.
- 응모권 사용 이벤트에서는 이벤트 추첨유형을 2가지 지원한다.
  1. 단일 상품을 참여자 모두가 추첨하는 방식
  2. 다중 상품에 대해 순위별 추첨하는 방식

### 수정 및 삭제 제한

- 시작 전에는 모든 설정을 수정할 수 있다.
- 진행 중에는 제목·설명·이미지를 포함한 이벤트 정보를 수정할 수 없다.
- 진행 중 경품·응모 비용·당첨 인원·마감 시각 등 참여 조건은 변경할 수 없다.
- 마감 후에는 이벤트 정보를 수정할 수 없다.
- 시작 전이며 참여 이력이 없는 이벤트만 삭제할 수 있다.
- 진행 중 이벤트를 강제로 중단·취소할 수 있으며, 해당 이벤트에 사용한 응모권을 반환한다.
- 중단·취소는 진행 중 정보 수정 제한과 구분한다.
- [추가 검토 필요] 중단·취소와 응모가 동시에 발생할 때의 처리 순서, 반환 시점, 만료된 응모권의 반환 후 유효기간을 정한다.
- 중단 취소가 진행된 후 반환되는 응모권의 기한은 해당 월로 처리한다. 중단취소 이후 일정 시간후 응모권을 사용자에게 반환해준다

### 상태 관리

- 진행 예정, 진행 중, 마감 , 추첨 완료·발표 대기, 발표 완료, 중단·취소 상태를 구분한다.
- 상태는 시스템에서 관리하며 관리자가 변경할 수 있다. 추첨 완료 → 발표완료 , 진행 예정 , 진행 중 , 마감 → 중단 으로 바꿀수 있음
- '응모자 없음'과 '추첨 대상자 없음' 종료 상태를 구분한다.

## 2. 기본 출석

- 일일 출석 시 응모권 1장을 지급한다.
- 동일한 일일 출석에 대한 중복 지급을 방지한다.
- 버튼 연타·새로고침·동시 요청·날짜 변경 경계에서도 같은 출석은 한 번만 반영한다.
- 출석 수행 기록과 응모권 지급 결과의 일치를 보장한다.
- 별도 출석 동작으로 출석을 인정한다.
- 출석의 사용자·이벤트별 초기화 시각은 00시이다.
- 00시 의 기준은 UTC

## 3. 주간 미션 — 보류

주간 미션은 추후 검토 대상으로 보류한다. 아래 내용은 도입 시 검토할 요구사항이다.

- 매주 초기화되는 반복 미션을 제공한다.
- 미션 내용, 완료 조건, 보상 응모권 수를 관리한다.
- 미션 수행 여부와 보상 지급 내역을 확인할 수 있다.
- 같은 미션 달성 건에 대한 중복 보상을 방지하고, 수행 기록과 지급 결과의 일치를 보장한다.


| 미션       | 달성 조건                     |
| -------- | ------------------------- |
| 연속 출석    | N일 연속 출석 시 달성             |
| 게임 플레이   | 게임을 N회 플레이하면 달성           |
| 게임 점수 달성 | 게임에서 지정된 목표 점수 이상 달성하면 달성 |


### 미정 사항

- 미션별 N값, 목표 점수, 응모권 보상 수량
- 주간 초기화 요일·시각·시간대
- 주차별 미션 달성·보상 가능 횟수 및 지급 방식
- 주차 경계를 넘는 연속 출석의 인정 방식
- 게임 플레이 횟수·목표 점수를 게임별로 판단할지, 여러 게임을 합산할지 여부
- 유효한 게임 플레이로 인정하는 기준

## 4. 일회성 미션

- 계정당 이벤트 기간 중 1회만 달성할 수 있는 미션을 제공한다.
- 미션 내용, 완료 조건, 보상 응모권 수를 관리한다.
- 동일 미션 달성 건의 중복 처리·보상 지급을 방지한다.


| 미션       | 달성 조건                           |
| -------- | ------------------------------- |
| 설문 참여    | 만족도 조사 등의 설문 완료                 |
| 브랜드 퀴즈   | LG유플러스 또는 이벤트 관련 퀴즈 참여 또는 정답 달성 |
| 장기 연속 출석 | 이벤트 기간 동안 장기간 연속 출석 달성          |


- 장기 연속 출석의 예시는 15일·20일이며, 실제 적용 일수는 미정이다.
- 브랜드 퀴즈의 참여만으로 달성하는지, 정답을 맞혀야 하는지는 미정이다.
- 설문 완료 기준, 퀴즈 재도전 기준, 미션별 보상 수량은 미정이다.
- 출석 누락 시 연속 출석 처리 방식과 장기 출석·주간 출석 미션의 중복 보상 여부는 미정이다.
- [추가 검토 필요] '이벤트 기간'이 어느 이벤트의 기간인지 불명확하다. 여러 이벤트가 동시에 진행되면 기준을 정할 수 없다. 15절의 공통 기간 단위 결정과 함께 확정한다.
- [추가 검토 필요] 장기 연속 출석 일수가 기준 기간보다 길어 달성할 수 없는 미션의 등록을 막을지 정의되지 않았다.

## 5. 게임

- 여러 종류의 게임을 제공한다.
- 게임은 순환 방식이 아닌 전체 게임을 한 번에 공개한다.
- 게임별 점수를 기록하며, 개인 최고점과 누적 점수를 함께 보관한다.
- 게임 점수는 서버가 판정한다.
- 게임은 횟수 제한 없이 이용할 수 있으나, 보상은 하루 1회 응모권 1장으로 제한한다.
- 게임 어뷰징 감지 방식은 추후 검토한다.

### 미정 사항

- 제공할 게임 종류 및 게임별 규칙 (후보: 타코야끼 만들기)
- 게임 결과·플레이 횟수의 유효성 검증 방식 (담당자 검토 윤태형)
- 재시도·중복 결과 제출의 처리 방식 ( 담당자 검토 윤태형)

## 6. 응모권 관리

### 적립 및 조회

- 기본 출석, 일회성 미션, 게임 플레이 횟수·점수 보상으로 응모권을 적립한다.
- 기본 출석 보상은 일일 1장으로 한다.
- 미션별 보상과 게임 플레이 횟수·점수별 보상 수량을 관리한다.
- 보유 응모권 수와 적립·사용 내역을 조회한다.
- 이력에서 수량, 사유, 발생 시각, 관련 행위를 확인한다.
- 포인트는 사용하지 않고 응모권으로 관리한다.

### 정합성 및 중복 방지

- 적립·사용 이력은 수정·삭제 없이 누적 기록한다.
- 정정이 필요하면 원본에 연결된 별도 이력을 추가한다.
- 이벤트 중단·취소 시 원본 사용 이력에 연결된 반환 이력을 추가하고 잔액과 함께 반영한다.
- 동일 사용 건의 반환 요청이 반복돼도 중복 반환하지 않는다.
- 이력 합계와 현재 보유 응모권 수의 일치를 보장한다.
- 동시 요청에서도 보유량을 초과해 차감할 수 없다.
- 같은 보상 건의 지급 요청이 반복돼도 한 번만 반영한다.

### 사용 범위·유효기간

- 응모권은 매달 초기화하며, 초기화 시점의 잔여 응모권은 소멸한다.
- 응모권 상태에 '기간 만료'를 추가한다.
- 만료 소멸도 이력으로 기록해 이력 합계와 잔액의 일치를 유지한다.
- 초기화 기준 시각과 시간대 00시 , 만료 직전 적립분의 처리 기준: 말일 이벤트 오픈

### 응모권 경제·운영

- 추첨 대상에서 제외된 사용자가 사용한 응모권은 반환한다.
- 관리자의 응모권 수동 지급·회수(CS 보정) 기능은 이번 버전에서 구현하지 않는다.
- 월말에는 응모권 사용 수량 상한이 없는 이벤트를 열어 잔여 응모권을 소진할 수 있도록 한다.
- 응모권의 유효기간은 월별로 나누어져있어 차감순서 필요 X

## 7. 이벤트 참여

- 이벤트 목록과 상세 정보를 조회한다.
- 참여 기간, 경품, 응모권 사용 여부, 멤버십 등급 조건, 추첨 방식, 가중치 규칙을 확인한다.
- 응모권 미사용 이벤트는 경품을 선택하지 않고 이벤트에 응모하며 응모권을 차감하지 않는다.
- 응모권 사용 이벤트는 모집 시간 내에 응모권을 사용해 응모한다.
- 가중치 적용 이벤트는 여러 장의 응모권 사용을 허용한다.
- 가중치 미적용 이벤트는 응모권 1장만 사용할 수 있다.
- 응모권 사용 가능 범위를 검증한다. 구체적인 범위는 6절의 정책 확정 후 적용한다.
- 같은 요청의 재시도와 새로운 응모를 구분해 중복 반영을 방지한다.
- 응모권 사용 이벤트의 차감·사용 이력·응모 기록은 함께 성공하거나 함께 실패하도록 처리한다.
- 응모권 미사용 이벤트도 같은 요청의 재시도로 응모 기록이 중복 생성되지 않도록 한다.
- 내가 참여한 이벤트와 응모 내역에서 사용 응모권 수, 처리 시각, 결과, 거절 사유를 확인한다.

### 응모 횟수 및 취소

- 응모권 미사용 이벤트는 사용자당 최대 1회 응모할 수 있다.
- 가중치 미적용 이벤트의 응모권 1장 제한은 이벤트 기준 1회를 뜻한다.
- 가중치 적용 이벤트는 추가 응모를 허용한다.
- 사용자의 응모 취소는 제공하지 않는다.
- 이벤트 중단·취소에 따른 응모권 반환은 1절의 확정 정책을 적용한다.

### 마감 판정

- 서버에서 마감 전에 승인한 응모만 인정한다.
- 정확히 마감 시각부터는 응모할 수 없다.
- 마감 전에 승인된 응모는 응답이 마감 후 도착해도 유효하다.
- 서버의 '승인 시점'을 어떤 처리 단계로 정의할지는 구현 설계 시 담당자(석종수)가 정한다.
- 응모권 사용 이벤트는 응모 완료 시점을 기준으로 하며, 추첨 시점의 접속 유지는 요구하지 않는다.

## 8. 실시간 참여 현황

- 총 참여자 수를 표시한다.
- 응모권 사용 이벤트에서 총 사용 응모권 수와 본인이 사용한 응모권 수를 표시한다.
- 원본 기록과 집계 결과의 일치를 보장한다.
- 당첨 확률은 표시하지 않는다.
- 현황을 자동 갱신하며, 응모 직후 결과를 바로 반영한다.
- 갱신 주기는 구현 담당자가 정한다.

## 9. 비정상 참여 탐지 및 관리자 검토

- 비정상 반복 참여를 탐지하고 사용자·이벤트·탐지 사유·발생 시각·관련 요청을 기록한다.
- 구체적인 탐지 조건·시간·횟수 기준은 미정이다.
- 탐지 사실만으로 자동 제외하지 않는다.
- 관리자가 참여 허용 또는 해당 이벤트의 추첨 대상 제외를 결정한다.
- 검토 상태, 검토자, 검토 시각, 사유를 기록한다.
- 제외 확정 전에 관리자가 사유를 확인·기록한다.
- 제외된 본인에게만 제외 사실과 사유를 안내하고 일반 낙첨과 구분한다.
- 구체적인 탐지 수치 및 다른 사용자 정보는 공개하지 않는다.
- 마감 검토는 마감 전 참여와 관련된 탐지 건을 대상으로 한다.
- 마감 후 단순 접속·재시도로 추첨 대기를 늘리지 않는다.
- 별도 이의 제기는 이번 버전에서 제외한다.
- 게임 점수·랭킹 보상에 같은 검토 절차를 적용할지는 미정이다.

### 적립 단계 비정상 행위 — 추가 검토 필요

- 응모 단계 외에 출석·미션·게임의 매크로·봇, 조작된 점수 등 적립 단계의 탐지 기준은 미정이다. 게임 어뷰징 감지는 5절의 추후 검토 사항과 함께 정한다. (담당자 검토 석종수)
- 요청 빈도 제한, 자동화 방지 수단의 적용 여부와 대상 기능은 정의되지 않았다. (담당자 검토 석종수)

## 10. 추첨 및 당첨자 관리 및 재추첨

### 추첨 대상 확정 및 실행

- 마감 전 승인된 유효 응모를 누락·중복 없이 반영한다.
- 미검토 탐지 건이 있으면 추첨을 보류한다.
- 관리자 검토 완료 후 제외 결과를 반영하고, 유효 응모 처리를 확인해 명단을 확정한다.
- 미검토 건이 없으면 유효 응모 처리 확인 후 명단을 확정한다.
- 응모권 미사용 이벤트는 명단 확정 후 관리자가 추첨을 실행한다. 마감·검토 완료만으로 자동 실행하지 않는다.
- 응모권 사용 이벤트는 모집 마감 후 바로 추첨
- 응모권 사용 이벤트 추첨의 자동 실행
- 15분 안에 검토가 끝나지 않은 탐지 건이 남았을 때 추첨을 보류
- 응모권이 필요한 이벤트의 추첨방식을 예를 들어 3등 5명이 당첨되면 그 5명을 제외하고 다시 추첨을 돌리고 2등 → 1등 이런식으로 처리하고 프론트엔드 쪽에서 시각화 하게 되는 방식 (프론트엔드 확인요망)

### 근거 보존 및 재현

- 응모자 명단, 응모권 수, 가중치, 조건을 별도 스냅샷으로 보관한다.
- 알고리즘에 필요한 시드 또는 추첨 키, 입력 순서, 버전 등 재현 자료를 보존한다.
- 관리자는 동일 입력·조건으로 결과와 당첨 순서를 재현하고 원본과의 일치를 확인한다.
- 재현·검증 과정에서 원본 결과를 보존한다.
- 사용자에게는 추첨 방식과 발표된 결과를 안내한다.
- 구체적인 알고리즘은 구현 단계에서 결정한다.
- [추가 검토 필요] 재현 가능성만으로는 공정성이 보장되지 않는다. 관리자가 시드를 고르거나 여러 번 실행해 원하는 결과를 선택할 수 없도록, 시드 생성 주체와 추첨 전 고정·공개 방식을 정해야 한다. (담당자 검토 석종수 )
- 스냅샷에는 응모자 명단이 포함되므로, 보존 기간과 탈퇴·개인정보 파기 시 처리 방식을 정해야 한다. (추후 검토 )

### 재추첨

- 재추첨은 관리자가 수동으로 할 수 있다
- 재추첨시 사유를 적고 재추첨 할수있게 구현한다
- 사용자에게 프론트적으로 보여주진 않는다.

### 가중치 및 중복 당첨

- 응모권 사용 이벤트는 가중치 적용·미적용 방식으로 구분한다.
- 가중치 적용 방식은 여러 장의 응모권을 사용할 수 있다.
- 가중치 미적용 방식은 응모권 1장으로 참여하며 참여자에게 동일한 추첨 가중치를 적용한다.
- 응모권 미사용 이벤트는 경품별 개별 응모가 아닌 이벤트 단위 응모를 기준으로 추첨하며, 참여자별 추첨 기회는 1회다.
- 한 이벤트에서 같은 경품이든 다른 경품이든 중복 당첨은 허용하지 않는다. 응모권 사용 이벤트도 동일하다.
- [재확인 필요] 사용 응모권 수를 가중치로 환산하는 계산식, 상한, 추가 배율을 정한다. (담당자 검토 석종수)
- 여러 경품·등수의 배정 순서와 이미 당첨된 참여자를 다음 경품 추첨에서 제외하는 처리 순서

### 대상 부족 및 결과 관리

- 유효 대상이 당첨 인원보다 적으면 전원 당첨시키고 나머지는 미선정으로 처리한다.
- 복수 경품·등수에서의 적용 단위와 부족 인원의 경품 배정 규칙은 미정이다.
- 응모자가 없으면 추첨 없이 '응모자 없음'으로 종료·표시한다.
- 전원 제외되면 추첨 없이 '추첨 대상자 없음'으로 종료·표시하고 본인에게 제외 사유를 안내한다.
- 당첨자 목록, 경품 내역, 당첨 순서, 관리자 실행 이력을 관리한다.
- 동시 실행·중단 후 재시도에도 하나의 결과만 확정한다.
- 사용자 요청에 의한 당첨 취소와 임의 재추첨은 제공하지 않는다.
- 발표 후 자격 미달·어뷰징·확인되면 해당 인원을 제외하고 재추첨한다. 기존 당첨자는 유지한다.
- 재추첨의 실행 주체, 허용 기한, 재발표 방식과 기존 당첨 결과의 보존 방법을 정한다.

## 11. 결과 발표 및 알림

- 추첨 결과는 이벤트 유형과 관계없이 관리자 확인 후 발표한다.
- 추첨 직후 자동 발표하지 않고 발표 대기로 보관한다.
- 발표 전 당첨 결과는 비공개로 유지한다.
- 마감부터 발표 전까지 '응모 마감 · 결과 발표 대기'를 표시하고 내부 검토 사유는 공개하지 않는다.
- 대상 없는 종료 표시와 제외 당사자 안내는 별도로 제공한다.
- 공개 결과에는 마스킹한 닉네임과 당첨 경품을 표시한다.
- 공개 화면과 응답 데이터 모두에 마스킹을 적용한다.
- 본인 화면에는 자신의 당첨 여부와 경품을 명확히 표시한다.
- 구체적인 마스킹 규칙은 미정이다.
- 발표 시 참여자 전원에게 결과 확인 알림을 생성한다.
- 대상, 내용, 발생 사유, 생성·모의 발송 시각, 처리 결과를 기록한다.
- 실제 이메일·푸시 대신 모의 발송한다.

## 14. 배너

- 노출 순서는 관리자가 정하는 걸로 한다
- 노출 기간은 없음 (관리자가 임의로 삭제 가능)
- 배너는 관리자가 수동으로 삭제 등록 수정 가능
- 이미지 용량은 구현시 정함
- 배너를 관리자 페이지에서 등록 수정 삭제할수 있다.
- 배너는 이미지 형식으로 진행되며 누르면 해당 이벤트페이지로 이동한다.
- 배너는 자동으로 슬라이드 형식으로 넘어간다 + 화살표로 양옆으로 이동가능
- 배너는 최대 5개까지 등록 가능하다.

## 14. 운영 및 시연 범위

- 기존 시연 방식은 로그인 화면에서 사용자 또는 관리자 역할을 선택해 진입한다.
- 가상 사용자 선택·전환으로 참여자별 데이터를 시연한다.
- 실제 회원가입·로그인·인증은 기존 범위에서 제외되어 있었다. '계정당 1회' 조건을 가상 사용자 기준으로 시연할지 실제 계정을 도입할지는 재확인이 필요하다.
- 시간 저장·비교는 UTC를 기준으로 하고 화면에서는 KST로 표시한다.
- 일일 출석은 별도 출석 동작으로 인정하며 사용자·이벤트별 00시에 초기화한다. 기준 시간대는 재확인한다.
- 응모권 월 초기화의 기준 시각도 같은 기준으로 정한다.
- 주간 미션은 보류 상태이며, 주간 미션·주간 랭킹의 기준 시각은 해당 기능 도입·유지 시 정한다.
- 적립부터 응모·검토·관리자 추첨·발표·검증까지 더미 데이터로 시연한다.
- 잔액 부족, 중복 요청, 검토 대기, 제외, 낙첨, 대상 없음 등 예외 상황을 포함한다.
- 더미 데이터에서도 이력·잔액·응모·추첨 결과의 정합성을 유지한다.
- 로딩, 빈 목록, 오류, 처리 성공 등 화면 상태를 안내한다.
- 실제 외부 알림 발송, 배송·결제는 이번 범위에서 제외한다.

## 1. 사용자 규모 및 요청량

- 이벤트당 참여자: 1,000명
- 동시 접속자: 100명
- 평시 요청량: 초당 20건(20 RPS)
- 마감 직전 요청량: 초당 100건(100 RPS)을 1분간 유지
- 동시 접속자와 초당 요청량은 별도로 측정한다.
- 테스트 전에 조회·응모 요청 비율과 데이터량을 고정한다.

## 2. 응답 시간 및 실시간 발표

- 조회 API: p95 500ms 이하
- 응모 API: p95 1초 이하
- 실시간 발표: 결과 확정 후 접속 사용자 화면 반영까지 p95 2초 이내
- 재접속한 사용자는 결과 조회 API로 확정 결과를 확인할 수 있어야 한다.
- p95는 전체 측정값의 95%가 해당 시간 이내라는 의미다.

## 3. 동시성 및 데이터 정합성

- 출석·미션 보상은 중복 지급되지 않아야 한다.
- 동시 응모에도 응모권 잔액이 음수가 되지 않아야 한다.
- 출석 기록과 보상 지급은 함께 성공하거나 함께 취소되어야 한다.
- 응모 기록과 응모권 차감은 함께 성공하거나 함께 취소되어야 한다.
- 추첨 요청이 중복되어도 결과는 한 번만 확정되어야 한다.
- 마감 시 진행 중인 응모의 처리 기준을 정하고, 추첨 대상 확정 후에는 대상 목록을 변경하지 않  
는다.
- 초기에는 DB 트랜잭션·유일 제약·조건부 차감을 적용하고, 부하 테스트 결과에 따라 보강한다.

## 4. 부하 테스트 합격 기준

- 테스트 도구: k6
- 평시 테스트: 20 RPS로 10분간 유지
- 마감 집중 테스트: 100 RPS로 1분간 유지
- 응답 시간: 조회·응모 API별 목표 충족
- 예상하지 않은 오류: 전체 요청의 1% 미만
- 정합성 오류: 중복 지급·초과 차감·중복 결과 확정 0건
- 마감·잔액 부족 등 정책에 따른 정상 거절은 시스템 오류와 구분한다.
- 같은 계정의 동시 응모와 중복 요청을 별도로 검증한다.
- 서버·DB 사양, 데이터량, 요청 비율을 테스트 결과에 기록한다.

## 5. 시연 로그인 및 관리자 보호

- 역할 선택 로그인은 데모 환경에서만 활성화한다.
- 관리자 권한은 역할 선택만으로 부여하지 않고 별도 인증을 거친다.
- 사용자 역할은 서버에서 결정하며, 클라이언트가 전달한 역할 값을 그대로 신뢰하지 않는다.
- 모든 관리자 API는 서버에서 인증·권한을 검사한다.
- 인증되지 않은 요청은 401, 권한이 없는 요청은 403으로 응답한다.

## 6. 이미지 저장소 및 배포 환경

- 이미지 저장소: S3 등 객체 저장소 사용
- DB 저장 정보: 이미지 파일 대신 저장소 키 저장
- 업로드 권한: 관리자만 허용
- 업로드 제한: JPEG·PNG·WebP, 파일당 최대 5MB
- 초기 배포 구성: 애플리케이션 1대 + DB
- 실행 환경: Docker 기반
- 통신: HTTPS 적용
- 비밀정보: 환경변수 또는 시크릿 관리 기능으로 관리하며, 저장소에 커밋하지 않는다.

## 7. 로그·모니터링·백업

- 요청 로그: 요청 ID, API 경로, 응답 상태, 처리 시간
- 오류 로그: 예외 내용, 요청 ID
- 운영 감사 로그: 추첨 실행·참여 제외·당첨 취소·정책 변경의 처리자, 시각, 사유
- 모니터링: CPU·메모리 사용량, 오류율, 응답 시간, DB 연결 수
- 민감정보 보호: 비밀번호·인증 토큰 기록 금지, 개인정보 마스킹
- DB 백업: 일 1회 수행, 7일 보관
- 복구 검증: 시연 전 백업 데이터 복구 확인

## 8. 발표 및 참여자 알림

- 추첨 결과 공개와 개인별 알림 생성을 분리한다.
- 결과는 확정 즉시 공개하고, 참여자 전원 알림은 비동기로 생성한다.
- 결과와 알림 생성 작업을 같은 DB 트랜잭션에 저장해 작업 누락을 방지한다.
- 별도 작업자가 참여자를 나누어 처리하고, 실패한 작업은 재시도한다.
- 이벤트·사용자·알림 유형을 기준으로 중복 생성을 방지한다.
- 알림 생성 목표: 참여자 1,000명 기준 결과 확정 후 30초 이내
- 재시도 후에도 실패한 작업은 기록하고 운영자가 재처리할 수 있어야 한다.
- 실제 문자·메일 발송은 제외하고, 모의 발송과 처리 결과 기록까지 구현한다.
- 실시간 발표는 참여자 전원의 알림 생성·발송 완료를 기다리지 않는다.
